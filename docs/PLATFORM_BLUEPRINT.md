## 1. 產品與收入模式

平台提供借址登記業者使用，延伸其企業客戶服務關係：
- 業者本身使用 LINE OA 客戶管理、成交追蹤與租戶維運。
- 租戶可加購 AI 官網、商城、租戶自己的 LINE OA 串接、CRM 等數位服務。
- 支援業者推薦分潤或經銷價差；比例、價格與結算條件皆為可設定資料，尚未定案。
- 地址合約與數位訂閱分開，企業搬離地址後可依約繼續使用數位服務。
- 數位訂閱款、地址服務款、租戶商城商品款分開建模及對帳。

## 2. 品牌與 UI

品牌：台灣創業園 / Taiwan Startup Park。
採 LINE OA 管理後台的視覺與操作習慣：白底、淺灰工作區、綠色主按鈕、左導覽、上方工具列。
不使用 LINE 商標冒充官方產品；品牌使用台灣創業園。
桌面：左導覽 + 工作區；手機：導覽抽屜，主要操作保持可用。
繁體中文；時間顯示 Asia/Taipei，資料時間以 UTC 保存。
支援載入、空狀態、錯誤、權限不足、未設定整合等真實狀態。
示範資料須明確標示，不得用模擬成功冒充真正發送、付款或開通。

## 3. 兩大工作區

### A. 成交追蹤

主階段：接觸 → 導入 → 收費 → 成交；另有暫緩、未成交。
- 來客來源、企業、聯絡人、需求、首次接洽者。
- 案件負責人、下一步、下次跟進時間、跟進歷程。
- 導入展示、試用、資料收集、方案。
- 報價版本、應收、付款期限、收款核對。
- 成交交接；記錄未成交原因，重新開案保留歷程。
- 付款狀態和案件階段分開；不能只改階段即視為付款。
- 同企業可多案件，既有租戶加購不得重複建企業。

### B. 租戶管理

成交後沿用企業與聯絡人資料：
- 租戶企業、多窗口、員工權限、服務承辦人。
- 登記據點、借址合約、信件／包裹、自取或轉寄。
- 維運申請與處理紀錄。
- 官網、商城、LINE OA、CRM 等功能的方案、期限、額度。
- 開通狀態與訂閱／付款狀態分開。已成交不等於已開通。
- 到期、續租、加購、暫停、恢復；不因地址退租立即刪除數位服務資料。
- 加購回到成交追蹤，完成後更新同一租戶。

## 4. 角色與資料隔離

避免把 operator（借址業者）和 business（進駐企業）都命名 tenant 而混淆。
建議角色：
- platform_admin：SaaS 業者開通、方案與系統管理。預設不讀取各業者聊天內容。
- operator_owner：該業者總管理員，可指派人員及核查該業者風險事件。
- operator_sales：被授權案件、聊天室及企業資料。
- operator_service：被授權租戶的日常維運。
- operator_finance：帳務及收款核對，不能改寫業務訊息。
- business_admin：自己企業的網站／商城／訂閱與授權員工。

所有 API、查詢、檔案下載及背景工作均核對 operator_id 和必要的 business_id。
角色及 actor_id 由伺服器 session 決定，不能採信前端傳入的操作者／角色。
平台管理員支援性存取須額外授權並留痕，不設定默認跨業者閱讀。
多企業聯絡人透過 membership 關聯；LINE 身分使用 provider/channel context，不能把 UID 當全平台唯一個人身分。
風險內容不得出現在一般 CRM API、搜尋、匯出、通知或前端預載資料中。

## 5. 工作聊天室與操作歷程

核心要求：一人一帳號；案件負責人與逐則實際回覆者分開。
- 客戶使用原 LINE OA；員工登入本平台回覆，平台透過 Messaging API 發送。
- 每則出站訊息保存 actor_id、時間、客戶／案件、內容、來源及發送狀態。
- 來源區分人工、AI 自動、AI 草稿經人工確認；保留確認者。
- 接手、指派、代班、轉交、報價變更、收款確認、匯出、案件異動均留紀錄。
- 送出失敗／狀態未明時不得顯示送達；API 成功也不等於客戶已讀。
- 轉交不得回寫歷史回覆者。
- 業務停權後阻止新操作，歷史身分保持可追溯。
- 同時操作以版本或其他併發控制防止重複接手、重複發送。
- 原生 LINE OA 後台回覆／外部私人通訊的紀錄與操作者不能假設可由 API 取得；資料缺口明確標示。

Webhook：
- raw body 簽章驗證；依 channel 解析業者；不得採信訊息內容中的租戶指示。
- webhookEventId 去重、事件時間排序、快速持久化後非同步处理。
- 正式訊息僅從授權且已配置的整合送出。
- 收回事件連動移除可見內容及衍生摘要，依保存政策處理。
- 訊息正文、OCR 及外部文件均視為不可信資料，不得作為 AI 執行系統指令的依據。

## 6. 管理員專用風控

風控橫跨兩大工作區，不成為一般業務的第三個工作區。
- 後端規則及 AI 分析公司授權範圍內的服務資料、案件與帳務。
- 規則命中與 AI 推論分開；案件列為待核查，由人工結案。
- 一般員工不顯示個案告警、分析分數、查核歷程；API 同樣拒絕存取。
- 通知僅發給該業者指定管理員；敏感詳情需登入，連結本身不構成授權。
- 核查狀態：待確認、處理中、正常結案、誤報、確認異常。
- 記錄資料缺口，不以沉默、聯絡方式或單一關鍵字直接判定截單。
- 不自動處分員工，不讀取其私人 LINE。
- 保留適用的公司通訊紀錄、分析目的告知、權限與保存政策。
- 實際規則、閾值、核准收款資料及告警收件人由授權管理員於私有設定管理，不寫進公開源碼。
- AI 不可自行發送客戶訊息或更改金流；模型不可用時顯示狀態，不假稱已完成判讀。

## 7. 數位租用功能

AI 官網：上傳名片／DM／社群網址 → 結構化資料 → 網站草稿 → 確認 → 發布。
社群內容讀不到則保留連結並請補素材；不繞過登入限制。
價格、資格、效果與規格缺資料時標記待補；來源、版本可追溯。
基礎介紹頁與付費官網分開，可依業者方案設定。
商城：各企業商品、訂單、金流分離；第一版每筆訂單單一企業，付款回呼驗證及冪等。
LINE OA：業者 OA 用於管理租戶，租戶自有 OA 用於其顧客經營。
訂閱與功能權益由後端校驗，試用、付款、訂閱啟用、實際開通不可混為一談。
分潤按約定實收與退款淨額結算；先記歸屬及結算資料，不預設代付或資金分帳。
價格、比例、LINE 方案、AI 額度、網域費等尚未定案，均可設定。

## 8. 建議技術方向（須由實作環境確認）

Cloudflare Workers + TypeScript；D1 關聯資料；R2 私有素材。
前端可採 React/Vite；依實際相容性與依賴選用。
Queue／排程用於後续 OCR、AI 與提醒，先保留介面；本輪不新增正式定時通知。
登入採經驗證身分與伺服器 session；本地測試身分僅在明確 local demo 模式允許，production 必須 fail closed。
最小核心實體：operators、staff_users、memberships、businesses、contacts、business_contacts、leads、opportunities、assignments、conversations、messages、activity_events。
後续實體：quotes、payments、contracts、service_requests、plans、subscriptions、entitlements、referrals、settlements、risk_events、risk_reviews、line_connections。
內部稽核不可由一般員工修改；訊息內容的保存與刪除依政策分開處理，不能宣稱永久不可刪除所有聊天內容。

## 9. 第一輪 Codex 任務：可操作基礎版

本輪交付限「LINE OA 風格工作台＋後端權限＋成交到租戶資料閉環＋操作歷程」。
完整規劃保留於本文件；不得一次把商城、AI、金流全部做成未驗證的假功能。

請執行：
1. 讀取 AGENTS.md（如有）、本文件與最新 repo 狀態；確認分支與未提交修改。
2. 由本規格分支建立 feature/foundation；保留既有檔案，不碰其他 repo/Worker。
3. 建立可本地運行的 Worker/前端、D1 migrations、套件鎖與 .dev.vars.example（僅欄位名稱／假值）。
4. 完成 desktop/mobile 版面，成交追蹤及租戶管理兩個工作區。
5. 實作企業／聯絡人、案件建立、搜尋篩選、指派轉交、階段推進、成交轉租戶；伺服器持久化。
6. 實作伺服器端角色/資料隔離與操作紀錄；準備兩家業者的純虛構 local fixture 做隔離驗證。
7. 聊天室先提供本地 adapter 可驗證逐則 actor attribution、來源及發送狀態；未接 LINE 時標「尚未串接」，不對真實用戶發訊息。
8. 管理員專區先有獨立權限與空狀態；未啟用規則／模型時標「尚未啟用」，不顯示假風險。
9. 官網、商城、LINE OA 功能租用清單先做可管理的開通需求，清楚區分「申請中」與「已啟用」；無整合不得標示已啟用。
10. 編寫 README 操作指引、環境變數表、測試與後续整合清單。
11. 完成 typecheck/build 與下列有意義的測試；截圖驗證桌面/手機主要流程。
12. 提交 feature 分支及 draft PR，回報實作範圍、驗證證據和缺少的設定。

最低驗收：
- A 業者 session 對 B 業者任何相關 API/資源均無權存取。
- 業務直接請求風控 API 被拒絕，回應中不含風控欄位。
- 同企業第二筆成交不重複建企業，重送成交操作不重複建租戶。
- S1 指派案件、S2 回覆、S3 接手：歷史實際操作者仍正確。
- 偽造 actor_id、角色或 operator_id 無法越權。
- 發送失敗不能標成功；重試不重複產生可見訊息。
- 已成交/未開通與已付款/未付款能正確獨立顯示。
- local demo 登入／fixture 不可於 production 啟用。
- 停權人員 session 不能繼續執行寫入。
- 手機無橫向溢出，表單有錯誤／空狀態。

## 10. 執行與部署界線

- 先盤點 Cloudflare 帳號、現有 Worker、build 設定與 D1/R2 綁定；不可從網址推定已可部署。
- 本輪不覆蓋 production、不套用遠端 migration、不啟用正式通知/金流/排程。
- staging 如需建立，提出確切資源及部署命令；不能沿用其他專案資料庫。
- 秘密透過環境或 secret 管道設定，不要求把真實金鑰放入文件、PR 或聊天。
- 每個工具步驟約兩分鐘回報進度；同一障礙無進展超過五分鐘，保存成果並回報原因，避免無限重試。
- 不要求重複確認已定案品牌、網址、版面風格、兩大工作區。
- 如缺 LINE/AI/金流憑證，完成可獨立驗證部分並準確列出限制。
- 未跑的測試明列未執行；文件、畫面、模擬 adapter 不等於正式串接完成。

## 改善內容

- 已登入工作台的初始化資料由 /me、/staff 及三份全量列表共 5 個 GET，改為並行身分／人員與按需總覽共 3 個 GET；總覽以 SQL 統計完整範圍，僅回傳 4 筆跟進，沒有預載所有租戶或對話。
- 頁面保留側欄與工作台外框，只更新標題及內容。版面收合觀察器只處理新加入的可收合區塊，不因每次一般文字或訊息變動掃描整份 DOM。
- GET 使用本次瀏覽器工作階段的記憶體快取，TTL 15 秒、最多 48 個項目，合併同一路徑進行中的請求。寫入前後、登出／切換身分及 401／403 清除；舊請求不能回填已變更的工作階段。客戶資料沒有寫入 localStorage，也沒有共用 CDN cache；後端 API 保持 Cache-Control: no-store。
- 租戶、案件及對話清單改用伺服器 keyset 分頁：預設 50 筆，最多 100；搜尋及案件階段在後端篩選。完整總數另行統計，不把當頁 50 筆當作總數。保留原陣列 API 相容；本次工作台使用 paged=1。
- 新增 0005_workspace_paging_indexes.sql：租戶／服務承辦、案件／案件承辦、企業案件關聯、對話及需求狀態索引；只新增索引，沒有資料刪除。
- 租戶維運與據點／方案讀取改用 D1 batch；訂閱資格查詢改為同一 SQL 判斷付款，移除逐訂閱額外請求。收款資格、可見財務／維運資料、操作人員及業者範圍保持原有後端驗證。
- 案件／租戶詳細資料的獨立讀取並行；維運分頁在 TTL 內重用資料。超過當頁範圍的租戶可從租戶分頁選取，再帶入維運台；不把前 50 筆視為全部租戶。
- 第一期借址、空白未議定分潤、LINE／金流／AI 未串接狀態保持不變；教學影片保留原版。
